## 0. 사전 조사
* AI Agent Harness, 선언형 Graph Spec, 플러그형 Adapter, MCP, Hook, CLI, Next.js 기반 Node Editor와 관련된 공식 문서·권장 방식·오픈소스를 웹에서 적극적으로 조사한다.
* 조사 결과를 그대로 복제하지 말고 Harnest 목적에 맞게 적용한다.

## 1. 확장 가능한 프로젝트 기반

* Web Studio를 중심으로 Core, Adapter, CLI, Validator, Test, Trace를 독립적으로 확장할 수 있게 구성한다.
* 새로운 Component, Adapter, Evaluator, Tool, Transport를 기존 Core의 대규모 수정 없이 추가할 수 있게 한다.
* 공개 API와 내부 구현을 구분하고 순환 의존성, 중복 타입과 중복 검증 로직을 방지한다.

## 2. HarnessSpec

* PRD에 맞는 단일 `harnest.yaml` Loader와 TypeScript 타입을 구현한다.
* `components`, `connections`, `entrypoint`, `runtime`, `tests`, `studio`를 처리한다.
* Core는 `studio` 정보를 실행에 사용하지 않는다.
* YAML 문법, Component 설정, 참조 무결성, Port·Connection 호환성과 필수 연결을 검사한다.
* 오류에는 코드, 경로, 관련 Component와 이해 가능한 원인을 포함한다.

## 3. Harness Core

* 검증된 Spec을 Runtime Plan으로 변환한다.
* Agent, Model, Prompt, Output을 실제로 연결해 실행한다.
* Streaming, Timeout, 취소, 오류 전달, 사용량과 기본 Trace를 지원한다.
* Core가 특정 AI Provider SDK나 Web Studio에 직접 종속되지 않게 한다.

## 4. 확장형 Model Adapter 시스템

* Core는 특정 AI Provider나 기본 Adapter를 내장하지 않고 공통 Model Adapter 인터페이스와 Registry만 제공한다.
* OpenAI 호환, Anthropic, Gemini, 로컬 모델 등의 공식 Adapter는 독립 패키지로 제공하며, 사용자가 필요한 Adapter만 프로젝트에 설치·등록해 사용한다.
* 제공되지 않는 Provider는 사용자가 별도 패키지 또는 로컬 모듈로 Custom Adapter를 구현·등록할 수 있게 한다.
* Adapter는 호출, Streaming, 모델 설정, 사용량, 기능 지원 여부와 오류 정규화를 공통 규격으로 제공한다.
* Adapter 개발용 타입, 등록 API, 최소 예제를 제공하고 중복 ID, 로딩 실패, 잘못된 구현과 미지원 기능을 명확히 처리한다.

## 6. CLI와 실행 예제

다음 명령을 실제로 구현한다.

```bash
harnest validate <file>
harnest inspect <file>
harnest run <file> --input <value>
harnest studio
```

* 실제 Model Adapter로 응답을 실행한다.
* Streaming 응답, 실행 시간, Token 사용량과 `runId`를 표시한다.
* 정상 Spec, 잘못된 Spec과 Custom Adapter 예제를 추가한다.
* Secret은 YAML에 직접 저장하지 않고 환경변수 등 안전한 참조 방식을 사용한다.
* `harnest studio`는 Web Studio와 로컬 Runtime을 사용할 수 있게 한다.

v1.1의 Graph·Loop·Component Registry·MCP·Tool·Trace 기능을 유지하면서, 사용자가 내부 Schema나 YAML을 직접 조립하지 않고 **연결·선택·Drag & Drop만으로 실제 Agent Harness를 완성**할 수 있게 한다. 계획에서 멈추지 말고 구현·E2E 검증·문서화까지 완료해라.

## 0. 조사 및 현재 구조 점검

* 기존 Connection, Credential, Adapter, MCP, Tool, Agent 실행 흐름을 먼저 추적한다.
* MCP 최신 명세와 공식 SDK, OAuth 2.1, Agent Skills, OpenAPI·JSON Schema, n8n의 Credential·Node 설정 UX를 공식 자료 중심으로 조사한다.
* 기존 Registry와 보안 경계를 재사용하며 중복 시스템을 만들지 않는다.

## 1. Connection·Credential Manager

* Provider, MCP, HTTP API, Tool Service, Local Runtime 연결을 한 번 등록하고 여러 Harness에서 재사용하게 한다.
* 생성·검색·수정·삭제·연결 테스트·상태 확인·재인증·연결 해제 UI를 구현한다.
* Secret과 Token은 안전한 로컬 Credential Store에 저장하고 `harnest.yaml`에는 Connection ID와 비민감 설정만 기록한다.
* 프로젝트·사용자 범위를 구분하고 Export·Trace·오류에 Credential이 노출되지 않게 한다.
* Node Inspector에서는 URL·Header·Token 반복 입력 대신 Connection 선택과 `Connect` 동작을 제공한다.

## 2. MCP 연결과 OAuth

* Streamable HTTP와 `stdio`를 구분해 적절한 연결 Wizard를 제공한다.
* HTTP MCP는 Protected Resource Metadata와 Authorization Server Metadata를 자동 탐색하고 OAuth 2.1 브라우저 인증, 안전한 로컬 Callback, Client 등록, Scope 동의, Token 갱신·폐기·재인증을 처리한다.
* `stdio`는 OAuth를 요구하지 않고 실행 명령·환경·권한과 연결 테스트에 집중한다.
* 연결 후 Tool 목록과 설명, Input·Output Schema, 위험 관련 Metadata를 자동 탐색하며 목록 변경도 갱신한다.
* 사용자가 Tool을 선택하면 설정 Form·Typed Port·Canvas Node 또는 Agent Tool 연결을 자동 생성한다.
* 인증 만료, Scope 부족, 서버 오류, 연결 단절과 재연결 상태를 이해하기 쉽게 표시한다.

## 3. Tool 플랫폼

* MCP 외 Tool도 공통 Manifest·Registry·Executor 규격으로 등록할 수 있게 한다.
* Catalog에서 Web Search, HTTP Request, File, Shell·Code Runner 등 실용적인 기본 Tool을 검색·설치·테스트·추가할 수 있게 한다.
* Code 실행은 작업 디렉터리, Timeout, 자원·권한 제한과 사용자 승인을 적용한다.
* Custom Tool Wizard에서 다음 방식을 지원한다.

  * OpenAPI 가져오기
  * HTTP Endpoint
  * Local Command
  * TypeScript Module
* 최소 입력이나 요청·응답 예제로 Schema와 Form을 생성하되 사용자가 수정할 수 있게 한다.
* Tool Package가 설치되면 Catalog, Inspector, Validator와 CLI에서 동일하게 인식돼야 한다.

## 4. Agent Tool 실행

* Agent에 연결된 Tool만 모델에 노출하고 Provider별 Tool Call을 공통 실행 흐름으로 정규화한다.
* 모델 요청 → Tool 선택 → 승인 → 실행 → 결과 반환 → 후속 모델 호출의 Multi-turn Tool Loop를 실제로 지원한다.
* 최대 Turn, Timeout, Token·비용 한도, 취소, Tool별 허용·거부와 오류 복구를 제공한다.
* 읽기·쓰기·외부 전송·파괴 가능 작업을 구분하고 위험 작업은 실행 전에 명확한 사용자 확인을 받는다.
* 각 Tool Call, 인자, 승인, 결과, 오류와 회차를 Trace에서 확인할 수 있게 한다.

## 5. Agent Skills

* 공개 Agent Skills 형식에 맞는 `SKILL.md`, `scripts/`, `references/`, `assets/`를 지원한다.
* 프로젝트 및 사용자 범위의 `.agents/skills/`와 Harnest 전용 위치에서 Skill을 탐색하고 로컬 폴더·Git·패키지로 추가할 수 있게 한다.
* 시작 시에는 이름과 설명만 Catalog에 제공하고, 선택·활성화될 때 지침과 필요한 리소스를 점진적으로 로드한다.
* Skill이 요구하거나 권장하는 Tool·Connection·권한을 분석해 누락 항목을 안내하고 한 번에 추가할 수 있게 한다.
* 실행 코드가 포함된 Skill은 출처·권한·실행 내용을 보여주고 명시적인 신뢰 승인을 요구한다.
* 활성화된 Skill과 사용한 리소스·Tool을 Trace에 기록한다.

## 6. n8n 수준의 Studio UX

* Agent의 Tool·Skill Port나 Edge의 `+` 버튼에서 호환 가능한 항목을 검색하고 선택 즉시 생성·연결한다.
* 필요한 Connection이 없으면 현재 흐름 안에서 연결 Wizard를 열고 완료 후 자동으로 돌아온다.
* Palette를 Components, Tools, Skills, Connections, Templates로 구성하고 검색·분류·최근 사용·즐겨찾기를 지원한다.
* Schema 기반 동적 Form, Resource·Action 선택, 연결 테스트, 기본값과 설정 누락 안내를 제공한다.
* 내부 Module 경로, JSON Schema, Port, OAuth Endpoint 등은 Advanced 영역으로 숨긴다.
* RAG, Web Research, Coding Agent, MCP Agent, Evaluation Loop Template을 실제 실행 가능한 상태로 제공한다.
* 핵심 Harness 생성·연결·실행 과정에서 YAML 수동 편집을 요구하지 않는다.

## 7. Onboarding·검증·문서

* 첫 실행에서 Template → Provider·MCP 연결 → Tool·Skill 선택 → 자동 Graph 생성 → Validate → Run → Trace 흐름을 안내한다.
* 표준에 맞는 로컬 OAuth·MCP 테스트 서버를 사용해 Discovery, 로그인, Token 갱신, Scope 오류, Tool 탐색·호출을 실제 프로토콜 E2E로 검증한다.
* `stdio`, Streamable HTTP, Connection 재사용, Custom Tool, Skill 활성화, Multi-turn Tool Loop와 Studio↔CLI 동일 실행을 테스트한다.
* 기존 v1.1 테스트와 보안 정책을 모두 유지하고 lint, typecheck, 전체 테스트, production build와 브라우저 E2E를 통과시킨다.
* 외부 서비스 실검증이 불가능한 항목은 성공으로 위장하지 말고 자동화 검증과 미검증 항목을 구분한다.
* Placeholder, Node별 Credential 중복 입력, 핵심 흐름의 수동 YAML 수정으로 완료 처리하지 않는다.

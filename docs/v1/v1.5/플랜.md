구현 경계는 아래처럼 고정한다.

```text
브라우저
  ↓ 사용자 인증·소유권·Rate Limit
Next.js AI 서비스 ─────→ Supabase Auth/Postgres/Storage/Vault
  ↓ Harnest Runtime Protocol        ↑ Host Provider API
별도 Node Harnest Worker ────────────┘
  ↓
Harnest Runtime / Tool / Model / Sandbox
```

- Harnest는 실행, checkpoint, trace, context 조립만 담당한다.
- 사용자·대화·메시지·파일·메모리·PKM·연결 credential의 소유자는 외부 서비스다.
- Harnest 패키지에는 Supabase, SQL, ORM, 인증, 제품 DB migration 의존성을 추가하지 않는다.
- Studio의 파일 저장소는 로컬 테스트용 provider 구현으로만 유지한다.
- LangGraph나 AutoGen을 도입하지 않고 기존 런타임을 확장한다.

조사에서 적용할 원칙:

- MCP Elicitation의 `form/url`, `accept/decline/cancel`, OAuth·secret의 URL 기반 처리를 적용한다. [MCP Elicitation](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)
- Pause 이전 상태의 영속화, JSON 직렬화, side effect 중복 방지는 LangGraph checkpoint 원칙을 따른다. [LangGraph Interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts), [Persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
- 원격 입력 대기와 인증 요구 상태는 A2A의 `input-required`, `auth-required` 개념과 호환 가능하게 매핑한다. [A2A Specification](https://github.com/a2aproject/A2A/blob/main/docs/specification.md)
- 전송은 표준 SSE의 `id`, `event`, `data`, `Last-Event-ID` 재연결 규칙을 사용한다. [WHATWG SSE](https://html.spec.whatwg.org/multipage/server-sent-events.html)
- Wire schema는 JSON Schema Draft 2020-12로 배포한다. [JSON Schema 2020-12](https://json-schema.org/draft/2020-12)

## 2. Runtime·Human Interaction·권한 Protocol

### 공통 타입

`@harnestai/protocol`을 브라우저에서도 사용할 수 있는 새 패키지로 만들고, 기존 Zod 4 schema에서 JSON Schema를 생성해 함께 배포한다.

```ts
type InteractionKind =
  | "select" | "input" | "form" | "file" | "oauth" | "permission";

type InteractionAction = "submit" | "decline" | "cancel";

type PermissionDecision =
  | "allow_once" | "allow_for_run" | "allow_always" | "deny";

interface InteractionRequest {
  id: string;
  runId: string;
  nodeId: string;
  taskId?: string;
  agentId?: string;
  kind: InteractionKind;
  requester: { kind: "harness" | "agent" | "tool" | "mcp"; id: string };
  title: string;
  message: string;
  blocking: "task" | "run";
  schema?: JsonSchema202012;
  data?: Record<string, unknown>;
  checkpoint: { revision: number; sequence: number; digest: string };
  createdAt: string;
  expiresAt?: string;
}

interface InteractionResponse {
  interactionId: string;
  checkpointDigest: string;
  action: InteractionAction;
  value?: unknown;
  permission?: PermissionDecision;
}

interface PermissionScope {
  harnessId: string;
  toolId: string;
  connectionId?: string;
  capability: "network" | "process" | "workspace-write";
  resource?: string;
}
```

- `select/input/form`은 primitive, enum, required, description, 길이·숫자 제한을 포함한 JSON Schema subset만 렌더링한다. 임의 중첩 UI schema는 이번 범위에서 제외한다.
- API key, access token, password는 form 값으로 받지 않는다. OAuth 또는 host 설정 URL을 이용한다.
- `file` 응답에는 바이트가 아니라 외부 `fileRef`, MIME, 크기, 해시만 넣는다.
- `oauth` 응답에는 token 대신 외부 서비스가 발급한 `connectionRef`만 넣는다.
- Interaction 값과 `contextRef`는 trace에서 제거하거나 해시 처리한다.

### Pause·Resume

`RunSnapshot.status`에 `paused`를 추가하고 다음을 저장한다.

- `pendingInteractions`
- 실행 중에만 유효한 permission grant
- 처리된 Interaction·Command ID
- pending Tool call과 이미 완료된 sibling Tool 결과
- 다음 model turn, task, agent, plan revision
- 마지막 확정 event sequence

Pause 순서:

1. 사용자 입력이 필요한 지점에서 side effect 실행을 중단한다.
2. `interaction.requested` 이벤트와 snapshot을 `RunStore.commit()`으로 원자 저장한다.
3. 독립적으로 실행 가능한 Team 작업은 계속 실행한다.
4. 실행 가능한 작업이 없고 blocking interaction이 남으면 `run.paused`를 emit하고 현재 stream segment를 정상 종료한다.
5. 응답이 들어오면 interaction ID와 checkpoint digest를 검증하고 `interaction.resolved` 후 checkpoint에서 재개한다.

재시작 시 이미 완료된 model/tool 결과를 재실행하지 않는다. 외부 Tool이 실행됐는지 확정할 수 없는 상태로 중단됐다면 자동 재호출하지 않고 `recovery_required` Interaction을 생성한다.

HarnessSpec 버전은 올리지 않는다. v0.3에 다음을 하위 호환 추가한다.

- `interaction` built-in component
- Agent용 `request_interaction` 내부 Tool
- MCP Elicitation → Interaction Protocol adapter
- `context`의 외부 provider source
- `memory`의 외부 provider namespace

### 권한 의미

| 결정 | 저장 및 효력 |
|---|---|
| `allow_once` | 현재 interaction digest와 Tool call ID에만 적용 |
| `allow_for_run` | `RunSnapshot`에 저장하고 해당 Run 종료 시 폐기 |
| `allow_always` | 외부 `PermissionProvider`에 Harness·Tool·Connection·capability·resource 단위로 저장 |
| `deny` | 현재 호출을 거절하고 Tool error를 모델에 전달 |

실효 권한은 `host 정책 ∩ Harness 정책 ∩ Agent template 정책 ∩ Connection 정책 ∩ 사용자 grant`다. 하위 에이전트는 부모 권한을 확대할 수 없다. Preview가 잘렸거나 resource가 확정되지 않은 요청은 `allow_always`를 허용하지 않는다.

## 3. 공통 HTTP/SSE·SDK·외부 Provider

### Runtime/Event Protocol v1

Wire event는 내부 `RunEvent`를 다음 envelope로 변환한다.

```json
{
  "protocolVersion": "1.0",
  "eventId": "evt_...",
  "runId": "run_...",
  "sequence": 42,
  "time": "2026-08-25T12:00:00.000Z",
  "type": "interaction.requested",
  "data": {}
}
```

공식 endpoint:

- `GET /v1/capabilities`
- `POST /v1/runs`
- `GET /v1/runs/:id/events`
- `GET /v1/runs/:id/snapshot`
- `POST /v1/runs/:id/commands`
- `DELETE /v1/runs/:id`

SSE는 `text/event-stream`, `id: <sequence>`, `event: <type>`, JSON `data`를 사용한다. `Last-Event-ID`와 `after`를 모두 지원하고 heartbeat comment를 전송한다. `commandId`와 interaction digest로 중복 응답을 차단한다.

기존 `/api/runs`, NDJSON, `stream()`, `invoke()`는 한 릴리스 동안 compatibility wrapper로 유지한다.

### SDK 패키지

- `@harnestai/protocol`: Zod schema, TypeScript 타입, JSON Schema
- `@harnestai/core`: 기존 런타임
- `@harnestai/sdk`: 브라우저·Node 공용 HTTP/SSE 클라이언트
- `@harnestai/sdk/node`: 현재 `Harnest.load()` 내장 실행
- `@harnestai/cli`: 공통 protocol 기반 CLI
- `@harnestai/adapter-*`: 기존 모델 adapter
- PyPI `harnestai`: 원격 HTTP/SSE SDK

TypeScript와 Python Run handle은 동일 기능을 제공한다.

- `create()`
- `events(after?)`
- `snapshot()`
- `command()`
- `respond()`
- `cancel()`
- `wait()`

Python은 선택대로 내장 런타임을 재구현하지 않는다. `HarnestClient`와 `AsyncHarnestClient`를 제공하고 `httpx` 기반 SSE parser를 직접 구현한다.

### 외부 Provider 계약

```ts
interface HostProviders {
  conversation?: ConversationProvider;
  memory?: MemoryProvider;
  cache?: CacheProvider;
  files?: FileProvider;
  connections?: ConnectionProvider;
  permissions?: PermissionProvider;
  runs: RunStore;
}
```

- `ConversationProvider.read`: revision과 cursor 기반 대화 이력을 읽는다. Assistant 메시지 저장은 host가 terminal event를 받아 수행한다.
- `MemoryProvider.search/upsert/delete`: `user`, `conversation`, `pkm` namespace와 출처를 지원한다.
- `CacheProvider.get/put/delete`: `context`, `provider-prompt` namespace, TTL, ETag, opaque JSON 값을 지원한다.
- `FileProvider.read/create/commit`: 외부 object storage의 파일·Artifact를 stream한다.
- `ConnectionProvider.resolve`: token을 노출하지 않고 Harnest outbound 요청에 필요한 credential을 주입한다.
- `PermissionProvider.list/find/grant/revoke`: `allow_always`만 저장한다.
- `RunStore.commit/readEvents/readSnapshot`: event와 checkpoint의 원자 저장을 담당한다.

분리 배포에서는 Worker가 DB credential을 갖지 않는다. Next.js의 내부 Host Provider API에 app-issued `contextRef`만 전달하며, 외부 서비스가 이를 사용자·대화 ID로 해석한다.

### Context·Memory·PKM·Cache·출처

- 최근 N개나 60KiB 같은 정책 제한을 제거한다. 남는 바이트 제한은 입력 공격 방지를 위한 안전 한도로만 사용한다.
- 모델의 `contextWindowTokens`, 출력 reserve, 기존 run budget으로 입력 예산을 계산한다.
- adapter가 token counter를 제공하면 사용하고, 없으면 UTF-8 기반 보수 추정치를 사용한다.
- 유지 우선순위는 system/Harness 지침 → 현재 요청 → unresolved Tool/Interaction → 원본 목표·계획·검증·남은 작업 → 최근 대화 → 장기 Memory·PKM 순이다.
- 오래된 대화는 기존 구조화 checkpoint 형식으로 압축하고, 원문은 외부 Conversation Provider에 남긴다.
- Context cache key에는 Harness digest, model, tool schema, conversation revision, memory revision, PKM revision을 포함한다.
- Provider prompt cache는 기존 구현을 유지한다. Gemini의 implicit/explicit caching, Anthropic cache breakpoint, OpenAI provider-managed caching을 adapter별로 계속 처리한다. [Gemini Context Caching](https://ai.google.dev/gemini-api/docs/caching), [Claude Prompt Caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [OpenAI Prompt Caching](https://openai.com/index/api-prompt-caching/)
- 외부 Context는 `ContextSource`로 정규화해 `S1`, `S2` 식별자를 부여한다. 모델 응답의 `[S1]` 표기를 검증해 `Citation`으로 반환하며 존재하지 않는 출처는 링크하지 않는다.
- Memory/PKM provider는 Mem0식 사용자 scope와 Graphiti식 provenance를 수용할 수 있게 하되 두 프로젝트를 의존성으로 추가하지 않는다. [Mem0 API 구조](https://github.com/mem0ai/mem0/blob/main/integrations/mem0-plugin/skills/mem0/references/api-reference.md), [Graphiti](https://github.com/getzep/graphiti)

### `/home/louis/Documents/Harnest_root/nextjs_ai`

Next.js 16·React 19·Base UI·Supabase 기반의 독립 앱으로 만든다.

화면:

- 좌측: 새 대화, 대화 검색·목록, 실행 중·대기 상태

제품 데이터는 앱 소유 Supabase schema에 저장한다.

- 대화·메시지
- 파일·Artifact
- 장기 Memory
- PKM source·chunk·embedding
- message source/citation
- run job·event·snapshot
- permission grant·cache entry

모든 사용자 테이블에 RLS를 적용하고 private Storage 경로도 사용자별로 분리한다. OAuth/API key는 Supabase Vault에 두며 Worker에는 전달하지 않는다. [Supabase Vault](https://supabase.com/docs/guides/database/vault), [Storage 접근 제어](https://supabase.com/docs/guides/storage/security/access-control)

실행 흐름:

1. Next.js가 Supabase session, conversation 소유권, Postgres 기반 rate limit을 검사한다.
2. 사용자 메시지와 파일 ref를 저장하고 `run_job`을 enqueue한다.
3. Worker가 app-owned internal API를 통해 lease 방식으로 job을 claim한다.
4. Worker가 Harnest를 실행하고 RunStore provider로 event/snapshot을 저장한다.
5. 브라우저는 Next.js SSE BFF를 통해 event를 받으며 sequence로 재연결한다.
6. Interaction 응답은 Next.js가 소유권을 다시 검사한 뒤 command로 전달한다.
7. terminal outcome은 앱이 assistant message, Artifact, Citation을 transaction으로 저장한다.

PKM은 Supabase `tsvector + pgvector` hybrid search provider로 구현하고 결과에 문서·페이지·chunk 출처를 유지한다. [Supabase Hybrid Search](https://supabase.com/docs/guides/ai/hybrid-search)

대표 HarnessSpec은 다음 흐름으로 만든다.

```text
Classifier
 ├─ direct: multimodal Agent
 ├─ research: Researcher + Web Search + PKM + Reviewer Team
 └─ engineering: Planner + Code Runner + File Tool + Reviewer Team
        ↓
Join → Evaluator → 제한된 수정 Loop → Output
```

- 이미지 평가는 multimodal 모델을 우선 사용한다.
- 코드 실행·파일 변환이 필요한 경우에만 sandbox를 사용한다.
- Firecrawl/SearXNG/MCP 도구 연결을 지원한다.
- 장기 Memory write, OAuth, 위험 Tool에는 새 Interaction/Permission Protocol을 사용한다.
